# Project Documentation

This directory will hold the reviewed project documents. The table below defines the document set; it does not mean that each deliverable has been completed or published.

| Area | Expected contents |
| --- | --- |
| [Project proposal](01_project_proposal.md) | Problem, users, aim, objectives, expected outcomes, and scope. |
| Evidence of relevance | Agreed, de-identified findings from user discussions or other permitted evidence, and their effect on requirements. |
| Literature review | Critical synthesis, a publication analysis table, and references. |
| Existing systems | Comparable systems assessed against shared criteria with sources. |
| Technology decisions | Alternatives, selection criteria, and reasons for the proposed choices. |
| Requirements | Functional and non-functional requirements, priorities, and acceptance criteria. |
| Architecture | Components, data flows, interfaces, access boundaries, and links to diagrams. |
| User experience | User scenarios, prototype references, and findings from walkthroughs. |
| Verification and evaluation | Technical checks, model baselines, metrics, and evaluation conditions. |
| [Project management](10_project_management/README.md) | Responsibilities, milestones, risks, dependencies, and YouTrack links. |
| Supervisor feedback | Received comments, resulting decisions, and changes addressing them. |

Use descriptive filenames and relative links between published materials. Record a document's scope, sources, and review information where appropriate. Add links here as the documents are published.

Supporting material belongs in [research](../research/README.md), [diagrams](../diagrams/README.md), and [prototypes](../prototypes/README.md). Follow the [contribution workflow](../CONTRIBUTING.md) when submitting changes.
