# Dataset audit template

Distinguish a metadata review from inspection of actual records. Do not infer a missing property from a dataset title or search result.

| Item | Evidence or unresolved question |
| --- | --- |
| Dataset name, owner, version, official URL | |
| Actual inspection date and scope: metadata / sample / full records | |
| Population, recruitment, setting, collection period | |
| Files, schema, and unit of analysis | |
| Row counts and unique participant counts | |
| Outcome definition, instrument, scoring, and independence from predictors | |
| Observation timestamps and information availability timestamps | |
| Repeated observations and stable linkage across time | |
| Candidate forecast horizon and overlap of measurement windows | |
| Missing values, duplicates, inconsistent values, and attrition | |
| Train/validation/test split feasibility and dependence | |
| Access conditions, licence, permitted purposes, and privacy constraints | |
| Suitability: suitable / conditional / unsuitable / unknown | |
| Reason, limitations, and next check | |

Record scripts and counts only after executing them on the stated version of the data. Metadata-only reviews must leave unverified record-level properties unresolved.
